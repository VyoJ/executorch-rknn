# RV1103 (Luckfox Pico Mini B)

The RV1103 is the RV1106's smaller sibling: the same Cortex-A7 core and NPU,
the same `librknnmrt.so` 1.6.0 and NPU driver 0.9.2, but 64 MB of DDR2 in the
package instead of 256 MB of DDR3. Everything in [rv1106.md](rv1106.md) applies
to it too. This page covers what is different.

## Memory

| | Mini B |
|---|---|
| RAM visible to Linux | 33 MB |
| NPU region (`rk_dma_heap_cma=24M`) | 24 MB |
| Available with `rkipc` stopped | about 18 MB |
| `/tmp` | 16 MB tmpfs, so files there use RAM |
| Root filesystem | flash, about 27 MB free |

Stage files on flash rather than in `/tmp`, or the model and runner take RAM
the model needs at run time:

```
REMOTE=/root/rknn-pte tests/device/run_rknn_pte.sh <pte> <dir>
```

What fits:

- int8 models whose weights live in the NPU region. MobileNetV2 peaks at
  7.0 MB RSS. MobileViT-XS, in 41 RKNN contexts with LayerNorm and attention
  on XNNPACK, peaks at 13.6 MB and leaves about 7 MB of RAM free while it
  runs.
- Not float models on the CPU. Float MobileNetV2 through XNNPACK alone holds
  its 14 MB of weights plus XNNPACK's packed copy and is killed by the kernel
  at 17 MB.
- Not MobileViT-XS as a single plain RKNN model, which asks for 80 MB of NPU
  memory and does not fit the RV1106's 66 MB either.

## The same files run unchanged

The `.pte` files and runners built for the RV1106 run on the Mini B as they
are, and give bit-identical outputs: all 100 MobileNetV2 check images and all
50 MobileViT-XS ones match the Pico Pro Max byte for byte. Building the
`.rknn` with `target_platform="rv1103"` gives a different file but the same
speed and accuracy.

## Speed

Same `.pte` files on both boards, `rkipc` stopped, mean of 100 runs:

| | Pico Pro Max (RV1106) | Pico Mini B (RV1103) |
|---|---|---|
| MobileNetV2, through the delegate | 10.6 ms | 14.7 ms |
| of which `rknn_run` | 9.1 ms | 12.0 ms |
| of which input quantisation | 1.5 ms | 2.6 ms |
| MobileViT-XS, RKNN and XNNPACK | 519 ms | 556 ms |
| MobileViT-XS, RKNN and portable kernels | | 1,973 ms |

The NPU runs about a third slower, and memory-bound CPU work such as the input
conversion about 1.7 times slower, consistent with the slower DDR2. Work that is
mostly CPU arithmetic, like MobileViT's attention on XNNPACK, is only about 7%
slower. The driver reports the NPU clock as 420 MHz (`/proc/rknpu/freq`).
